# DSH 0.2.2 适配记录

## 0.2.2-rc.3

Sidechain 版本、DSH 开发依赖及锁文件更新到 `0.2.2-rc.3`，包与插件清单、DSH peer dependencies 的兼容范围同步为：

```text
>=0.2.1-rc.2 <=0.2.1-rc.5 || >=0.2.2-rc.1 <=0.2.2-rc.3
```

对比官方 RC.2 与 RC.3 包，插件依赖的子会话启动、命令、会话投影、工具限制、输入菜单和原生侧栏接口没有变化。工作区包新增的选择器 Factory 不影响当前插件。业务源码无需修改；重新构建的 Host/Client 产物与已发布 RC.2 的 `lib/` 完全一致。

2026-11-16 验证：

- `pnpm check` 通过两侧类型检查、49 项测试及构建。没有新增运行时逻辑或重复测试。
- 官方 RC.3 兼容检查先确认旧清单被拒绝，再确认新清单接受上述七个版本，拒绝 `0.2.1-rc.1`、`0.2.1-rc.6`、`0.2.1`、`0.2.2-rc.4` 和 `0.2.2`。
- 打包后通过官方 RC.3 CLI 安装到独立 Web profile，无版本豁免。真实模型和浏览器验证命令图标及名称、BTW 上下文继承与只读、父草稿保留、SIDE 读文件和续聊记忆、同一侧栏中的多个标签、`/side list`、父日志隔离及刷新恢复，未出现页面异常。
- 已核对实际 CLI、Session、Subagent、LLM 均为 RC.3，安装的 Host/Client 文件与仓库构建产物逐字节一致。证据保存在忽略入库的 `dist/rc223-compatibility/`，复用上一轮的验证脚本。

### 0.2.1 支持评估

目前支持的是 `0.2.1-rc.2` 至 `0.2.1-rc.5`，不包含 `0.2.1` 正式版。保留它们方便尚未升级的用户；没有使用率数据可以证明这些用户已经全部迁移。其维护成本主要是四个旧宿主的验证矩阵以及 Cordis `4.0.5` 的兼容声明。

旧 `request` 启动格式和对应回归测试也服务于 `0.2.2-rc.1`，所以单独停止 `0.2.1` 支持不能删除这条兼容路径。本轮保留既有支持范围。若后续需要减少兼容代码，合理的边界是最低支持 `0.2.2-rc.2`，同时停止维护 `0.2.1` 和 `0.2.2-rc.1`；旧宿主可固定到已发布的插件 `0.2.2-rc.2`（提交 `8a9cce1590bff76183d68d2f35a2c72c2fb34da2`）。

本轮未重复运行旧宿主全矩阵，沿用 RC.2 的验证记录；未复测 Desktop/Electron、跨版本数据迁移、完整附件交互或长历史场景。市场索引在源码及构建产物提交后按发布流程生成。

## 0.2.2-rc.2

Sidechain 版本、开发依赖及锁文件更新到 `0.2.2-rc.2`，重新生成发布用 `lib/`。包与插件清单的兼容范围为：

```text
>=0.2.1-rc.2 <=0.2.1-rc.5 || >=0.2.2-rc.1 <=0.2.2-rc.2
```

RC.2 将 `startActivation` 的 `parent`、`prompt` 从 `request` 移到顶层，并移除了服务上的 `listChildren`。插件在共享的启动入口适配两种参数格式：仍提供 `listChildren` 的已支持旧宿主使用原格式，RC.2 使用顶层参数。`/side list` 改为读取当前会话的 `subagentCatalog` 和 `sidechainModes` 投影，继续列出所有直接子会话并保留 BTW 身份，不扩展为递归后代列表；投影不可用时显式报错。

Zod 最低版本更新为 `4.6.6`，与 RC.2 的投影校验接口对齐。原生侧栏、命令菜单与前端构建产物无需修改，没有修改 DSH 源码。

2026-11-13 验证：

- `pnpm check` 通过 Host/Client 类型检查、49 项测试和构建。回归覆盖新版启动参数、旧版启动格式、直接子会话列表及缺失投影错误。
- 同一个打包产物通过官方 RC.2 CLI 安装到独立 Web profile，无版本豁免。真实模型验证 `/btw` 继承已完成上下文且只读、父输入草稿保留、`/side` 读取文件及续聊记忆、多个侧会话共用侧栏标签、`/side list`、父日志隔离、刷新恢复与重新打开 BTW。
- 最早支持的官方 `0.2.1-rc.2` 使用另一个独立 Web profile 安装同一产物，上述真实模型和浏览器流程全部通过，验证旧版启动格式与升级后的 Zod 仍可用。其余已支持旧版沿用此前验证，本轮未逐版复测。
- 官方兼容检查接受上述六个宿主版本，拒绝 `0.2.1-rc.1`、`0.2.1-rc.6`、`0.2.1`、`0.2.2-rc.3` 和 `0.2.2`。范围边界检查不代表这些版本均有本轮运行验证。

本轮浏览器证据位于忽略入库的 `dist/rc222-compatibility/`。未复测 Electron、附件完整交互、跨版本数据迁移、PTC 实际模型调用或长历史场景；之前用户确认的 Desktop 安装与使用记录仍适用于当时版本。

## 0.2.2-rc.1

Sidechain 版本跟随目标宿主，更新为 `0.2.2-rc.1`。开发依赖及锁文件固定到对应官方 DSH 包，Cordis 更新为 `4.1.0`，Schemastery 更新为 `3.19.0`，重新生成发布用 `lib/`。没有修改 DSH 源码。

同一个插件包支持以下范围，包清单、插件清单和 DSH peer dependencies 保持一致：

```text
>=0.2.1-rc.2 <=0.2.1-rc.5 || 0.2.2-rc.1
```

两段范围是明确的并集，不包含未经验证的 `0.2.1` 正式版、中间版本或后续版本。Cordis peer 范围为 `4.0.5 || 4.1.0`，对应两代实测宿主。

## 接口调整

1. **等待投影注册完成。** 新版 `sessionProjections.register()` 的合同要求先等待注册，再发布消费者。插件 `apply()` 改为异步，首先等待 `sidechainModes` 就绪，再安装命令和相关生命周期逻辑。投影使用新版 `ProjectionDefinition<'sidechainModes', SidechainModes>`，删除已废弃的 `SessionProjectionStateMap` 扩展；状态结构与 `stateVersion: 2` 不变。旧宿主也已实测支持这一加载流程。
2. **按完整图片引用读取附件。** 新版 `SessionAttachmentRequest` 需要 `attachment: ImageAttachmentRef`，宿主会校验格式、字节长度和尺寸。侧栏传入日志中的完整引用，同时保留旧宿主所需的 `attachmentId`。官方普通 RPC 编解码会移除未知字段，新旧宿主分别消费自己认识的字段；没有添加运行时版本判断或失败重试分支。
3. **对齐真实工具执行测试。** DSH 已将单次工具执行入口迁移至批处理 pipeline；原有权限测试改用官方 `executeToolBatch`，继续验证禁止工具、子会话本地工具、卸载重载和父会话不受影响。插件的工具限制实现无需改变。

投影就绪和图片读取的回归用例均先观察到旧实现失败，再验证修复通过。两个 TypeScript 检查及 Host/Client 构建通过；原有完整测试运行加修复后的受影响文件复测，合计 128 项用例全部通过。

- 五版 `/btw` 均继承父代号，侧栏没有续聊输入框；`/side` 通过真实 `read` 读取文件并在追问时记住两项信息。刷新及停止、重启实际宿主进程后，BTW 身份和历史仍正确，SIDE 可继续真实模型对话。父日志不包含子文件值、子回答或子代理通知。

## 证据与范围

一次性脚本、安装包、截图和真实会话记录位于忽略入库的 `dist/rc221-compatibility/`，按 `rc221`、`rc2`、`rc3`、`rc4`、`rc5` 分目录保存。每版包含 `versions.json`、`results.json`、`side-tool-real.png`、`cold-btw-real.png`、`final-real-browser.png`；新版和 RC.2 另有 `image-real.png`、`stream-real.png`、`readonly-real.png`。本地启动信息包含认证信息，不应发布原始 `ready.json`、浏览器存储状态或宿主日志。

五个宿主使用独立数据目录，不代表旧宿主可以读取新版写入的数据，也未覆盖旧数据跨版本迁移、Electron、PTC 实际模型调用或 #11 的长历史场景。本次不改变 #5 的完成回合继承限制。历史问题分析仍见 [0.2.1 记录](dsh-0.2.1-compatibility.md)。

市场索引固定到已提交源码。发布时先提交源码及 `lib/`，再运行 `pnpm build:market` 并提交、推送生成的索引；版本、兼容范围和安装 SHA 均从该源码提交派生。
